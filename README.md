# 📦 Қазпошта сәлемдемелерін жеткізу және трекинг жүйесі

## 1. Жоба туралы

Бұл — 16-нұсқа бойынша Қазпоштаның сәлемдемені тіркеу және трекинг процесін модельдейтін оқу жобасы.

- **Тілі:** Java 17
- **Қосымша түрі:** консольдік мәзір
- **Деректер қоры:** SQLite + JDBC
- **Құрастыру:** Maven
- **Тестілеу:** JUnit 5

Бұл жоба Қазпоштаның ресми ішкі жүйесі емес және нақты жөнелтілімдерді қадағаламайды. Деректер оқу мақсатында енгізіледі; Қазпоштаның ішкі деректері қолданылмайды.

## 2. Проблема және шешім

**Проблема:** сұрыптау немесе тасымалдау кезеңінде жаңа ақпарат уақытында енгізілмесе, пайдаланушы жүйеден тек соңғы сақталған ескі статусты көруі мүмкін.

**Оқу жобасындағы шешім:** пошта қызметкері расталған жаңа статус пен түсініктемені енгізеді. Жүйе статус ауысуын тексеріп, уақыт белгісімен TrackingEvent қосады және ағымдағы статус пен оқиға тарихын SQLite-ке бір транзакциямен сақтайды. Кейін трек-нөмір бойынша іздегенде соңғы сақталған статус және тарих көрсетіледі.

Жүйе GPS, автоматты сканерлеу немесе Қазпоштаның нақты уақыттағы серверімен интеграция ұсынбайды.

## 4. Негізгі мүмкіндіктер

1. Жіберуші, алушы, бөлімше және салмақ мәліметтерімен сәлемдемені тіркеу.
2. Бірегей KZ трек-нөмірін автоматты түрде генерациялау.
3. Трек-нөмір арқылы іздеу және статус тарихын көру.
4. Барлық сәлемдемелерді көрсету.
5. Рұқсат етілген ережелер бойынша статус жаңарту және оқиға тарихын сақтау.
6. Статус бойынша статистика және алушының атымен іздеу.
7. Стандартты және жедел жеткізу құнын Strategy үлгісімен есептеу. Формулалар — оқу мақсатындағы шартты мәндер, ресми Қазпошта тарифтері емес.
8. CSV есепті экспорттау және CSV жолдарын оқу.
9. CSV есепті ExecutorService және CompletableFuture арқылы фондық ағынмен экспорттау.
10. SQLite-ке сәлемдеме мен статус тарихын бір транзакциямен сақтау.

## 5. OOP және Java талаптары

- **Инкапсуляция:** private өрістер, конструкторлық тексерулер, қауіпсіз коллекция қайтару.
- **Мұрагерлік:** Sender және Recipient → Person; ParcelDao → Repository<Parcel>.
- **Абстракция:** abstract Person және Repository<T>; DeliveryStrategy интерфейсі.
- **Полиморфизм:** Person рөлі және DeliveryStrategy іске асырылымдарын ауыстыру.
- **Enum:** DeliveryStatus.
- **Collections:** List, Set, Map; ArrayList, HashSet, HashMap.
- **Generics:** Repository<T>.
- **Stream API:** filter, map, groupingBy, counting.
- **Custom exceptions:** TrackingNumberNotFoundException және DataAccessException.
- **ДҚ:** SQLite + JDBC + DAO + транзакциялар.
- **Файл:** CSV.
- **Көп ағындылық:** ExecutorService және CompletableFuture.
- **Тесттер:** JUnit 5.

## 6. Бағдарламаны VS Code-та іске қосу

Компьютерде JDK 17 және Maven болуы керек. WSL қолданылса, VS Code терминалында Ubuntu профилін пайдаланыңыз (терминал жолы `aiym@...$` болып басталады, PowerShell `PS C:\` емес).

Репозиторийдің негізгі бумасында:

```bash
java -version
mvn -version
mvn clean verify
mvn exec:java
```

Бірінші командада Java 17, екіншісінде Maven нұсқасы көрінуі керек. `mvn clean verify` компиляция мен JUnit тесттерін орындайды. `mvn exec:java` `kz.kazpost.Main` класынан консоль мәзірін ашады.

Бағдарлама алғаш іске қосылғанда `data/kazpost.db` файлын және кестелерді автоматты жасайды. CSV есеп әдепкіде `data/parcels-report.csv` файлына сақталады. Мәзірдегі 8-нұсқа фондық экспортты іске қосады.

## 7. JUnit тесттері

`mvn test` немесе `mvn clean verify` командалары JUnit 5 тесттерін орындайды. Тесттер:
- модельдердің валидациясын және статус ауысуын;
- Person мұрагерлігі мен полиморфизмін;
- SQLite DAO сақтау/іздеу/жаңартуын;
- ParcelService статистикасын және Stream API операцияларын;
- CSV экспорт пен оқуды;
- жеткізу стратегияларын;
- трек-нөмір генерациясын;
- асинхронды экспортты тексереді.

GitHub Actions-тағы **Java 17 Maven CI** workflow әр push және Pull Request кезінде `mvn clean verify` орындайды.

## 8. Демонстрация скриншоттары

Жергілікті VS Code іске қосу аяқталғаннан кейін мына дәлелдерді `docs/screenshots/` бумасына қосу керек:
1. консоль мәзірі ашылған сәт;
2. сәлемдеме тіркеу және трек-нөмір алынған нәтиже;
3. трек-нөмір бойынша іздеу және статус тарихы;
4. статус жаңартылған нәтиже;
5. CSV есебінің жасалғаны;
6. `mvn clean verify` нәтижесіндегі BUILD SUCCESS.

Скриншоттар әлі тіркелмеген; оларды нақты іске қосу нәтижесінен кейін қосу қажет.
