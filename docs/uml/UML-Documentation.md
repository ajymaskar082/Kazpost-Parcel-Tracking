# UML диаграммалары және деректер қорының сипаттамасы

## 1. Жобалау мақсаты

Бұл құжатта «Қазпошта сәлемдемелерін жеткізу және трекинг жүйесінің» UML диаграммалары мен деректер қорының бастапқы схемасы сипатталады. Диаграммалар жүйенің құрылымы мен мінез-құлқын код жазудан бұрын модельдеу үшін жасалған.

Жобалау кезеңінде мәселе UML диаграммаларында шешіліп қоймайды: диаграммалар проблемалық процесті және болашақ жүйенің құрылымын көрсетеді, ал нақты шешім Java кодында іске асырылады.

## 2. Use Case диаграммасы

**Файлдар:** `use-case.puml`, `use-case.png`

Use Case диаграммасы жүйемен әрекеттесетін сыртқы актерлерді және олардың мүмкіндіктерін көрсетеді. Диаграммада 6 актер бар: Жіберуші, Алушы, Пошта қызметкері, Курьер, Әкімші және Хабарландыру қызметі.

Негізгі қолдану жағдайлары: сәлемдемені тіркеу, трек-нөмір беру, іздеу, статусты және тарихты көру, статус жаңарту, тасымалдау, жеткізу, хабарлама жіберу, есеп қалыптастыру, CSV экспорттау және пайдаланушыларды басқару.

## 3. Class диаграммасы

**Файлдар:** `class-diagram.puml`, `class-diagram.png`

Class диаграммасы кластарды, атрибуттарды, әдістерді және олардың байланыстарын көрсетеді.

Тапсырмадағы негізгі жеті класс толық көрсетіледі:
- `Parcel` — сәлемдеме;
- `Sender` — жіберуші;
- `Recipient` — алушы;
- `PostOffice` — пошта бөлімшесі;
- `TrackingEvent` — статус оқиғасы;
- `DeliveryStatus` — статус `enum`;
- `ParcelService` — бизнес-логика.

Қосымша жобалық элементтер: `Person` абстрактілі класы, `DeliveryStrategy` интерфейсі және оның екі іске асырылымы, Generic `Repository<T>`, `ParcelDao`, `DatabaseConnection`, `TrackingNumberGenerator`, `CsvStorage` және `TrackingNumberNotFoundException`.

Диаграммада мұрагерлік, интерфейсті іске асыру, ассоциация, композиция және тәуелділік көрсетілген. `Repository<T>` Generics талабына, ал `ParcelDao` DAO үлгісіне жобалық негіз береді.

## 4. Sequence диаграммасы

**Файлдар:** `sequence-diagram.puml`, `sequence-diagram.png`

Sequence диаграммасы жіберушінің трек-нөмір арқылы сәлемдеме статусын іздеу сценарийін көрсетеді.

**UML-де көрсетілген проблема:** сәлемдеменің статусы уақытында жаңартылмаса немесе статус оқиғасы тарихқа тіркелмесе, жіберуші деректер қорында сақталған ескі немесе толық емес ақпаратты көруі мүмкін.

**Шешім UML-де емес, Java кодта іске асырылады:** кодтау кезеңінде статус жаңартуды және `TrackingEvent` жазбасын бір транзакциямен сақтау, деректерді тексеру және қате жағдайда `ROLLBACK` орындау қарастырылады.

## 5. Activity диаграммасы

**Файлдар:** `activity-diagram.puml`, `activity-diagram.png`

Activity диаграммасы сәлемдемені тіркеу және жеткізу барысындағы әрекеттерді, тексеру шарттарын, бірегей трек-нөмір генерациясын, деректер қорына сақтауды және қате жағдайларын көрсетеді.

## 6. State диаграммасы

**Файлдар:** `state-diagram.puml`, `state-diagram.png`

State диаграммасы сәлемдеменің өмірлік циклін сипаттайды. Негізгі күйлер: `REGISTERED`, `ACCEPTED`, `IN_TRANSIT`, `ARRIVED_AT_OFFICE`, `DELIVERED` және `LOST`. Күйлер арасындағы ауысулар жеткізу оқиғаларына байланысты орындалады.

## 7. ER диаграммасы және деректер қоры схемасы

**Файлдар:** `er-diagram.puml`, `er-diagram.png`

ER диаграммасы SQLite деректер қорындағы кестелер мен олардың байланыстарын көрсетеді:

1. `senders` — жіберушілер;
2. `recipients` — алушылар;
3. `post_offices` — пошта бөлімшелері;
4. `parcels` — сәлемдемелер;
5. `tracking_events` — статус тарихы.

Кестелерде Primary Key (PK), Foreign Key (FK) және бірегей трек-нөмір шектеуі қарастырылған. Бір жіберуші, алушы немесе пошта бөлімшесі бірнеше сәлемдемемен байланыса алады; бір сәлемдемеде бірнеше tracking event болуы мүмкін.

## 8. Қорытынды

Жобалау нәтижесінде Use Case, Class және Sequence негізгі UML диаграммалары, қосымша Activity және State диаграммалары, сондай-ақ SQLite деректер қорының ER схемасы дайындалды. Олар жүйенің актерлерін, кластарын, негізгі сценарийін және деректер моделін анықтайды. Келесі бағдарламалау кезеңінде осы жобалық шешімдер Java 17+ тілінде іске асырылады.
