# UML диаграммалары және деректер қорының сипаттамасы

## 1. Жобалау мақсаты

Бұл құжатта «Қазпошта сәлемдемелерін жеткізу және трекинг жүйесінің» актерлері, Java кластары, негізгі сценарийі және SQLite деректер қоры сипатталады. Негізгі үш UML диаграммасы — Use Case, Class және Sequence. Қосымша ретінде Activity, State және ER диаграммалары берілген.

Диаграммалар кодпен сәйкестендірілді. Диаграммада нақты іске асырылмаған хабарландыру, пайдаланушы аккаунты, GPS немесе автоматты курьерлік бақылау функциялары жүйенің бар мүмкіндігі ретінде көрсетілмейді.

## 2. Use Case диаграммасы

**Файлдар:** `use-case.puml`, `use-case.png`

Диаграммада 5 бизнес-актер бар: Жіберуші, Алушы, Пошта қызметкері, Курьер және Әкімші. Негізгі сценарийлер қолданыстағы консоль мәзірінің нақты функцияларына сәйкестендірілген: сәлемдемені тіркеу, трек-нөмір беру, іздеу, статус тарихын көру, статус жаңарту, статистика, жеткізу стратегиясын таңдау және CSV есепті синхронды/асинхронды экспорттау.

**Ескерту:** бұл актерлер бизнес-рөлдерді көрсетеді. Қазіргі бағдарламада жеке аккаунт, рөлге қарай кіру немесе әр актерге жеке рұқсат беретін авторизация жүйесі жоқ; барлық әрекет бір консоль мәзірінде орындалады.

## 3. Class диаграммасы

**Файлдар:** `class-diagram.puml`, `class-diagram.png`

Class диаграммасы Java кодында бар негізгі кластарды, атрибуттарды, әдістерді және байланыстарды көрсетеді.

Тапсырмадағы негізгі жеті класс:
- `Parcel` — сәлемдеме деректері мен статус тарихы;
- `Sender` — жіберуші;
- `Recipient` — алушы;
- `PostOffice` — пошта бөлімшесі;
- `TrackingEvent` — статус оқиғасы;
- `DeliveryStatus` — жеткізу статустарының enum түрі;
- `ParcelService` — бизнес-логика.

Қосымша нақты іске асырылған құрылымдар:
- `Person` — `Sender` және `Recipient` үшін ортақ абстрактілі класс;
- `DeliveryStrategy` — жеткізу бағасын есептейтін интерфейс; `StandardDeliveryStrategy` және `ExpressDeliveryStrategy` оны іске асырады;
- `Repository<T>` — Generic абстрактілі репозиторий; `ParcelDao` одан мұра алады;
- `DatabaseConnection` — SQLite JDBC қосылымы және схема инициализациясы;
- `TrackingNumberGenerator` және `ParcelFactory` — бірегей нөмір және объект құру;
- `CsvStorage` және `AsyncReportService` — CSV экспорт және фондық экспорт;
- `ConsoleMenu`, `Main` — консоль интерфейсі мен бағдарлама іске қосылуы;
- `TrackingNumberNotFoundException`, `DataAccessException` — арнайы қателер.

OOP сәйкестігі:
- **Инкапсуляция:** модель өрістері private, мәндер конструкторда тексеріледі.
- **Мұрагерлік:** Sender/Recipient → Person; ParcelDao → Repository<Parcel>.
- **Абстракция:** Person және Repository<T> абстрактілі кластар, DeliveryStrategy интерфейсі.
- **Полиморфизм:** Person сілтемесі арқылы Sender/Recipient рөлін алу; ParcelService ішінде DeliveryStrategy іске асырылымдарын ауыстыру.
- **Enum:** DeliveryStatus.

## 4. Sequence диаграммасы

**Файлдар:** `sequence-diagram.puml`, `sequence-diagram.png`

Sequence диаграммасы нақты іске асырылған «сәлемдеме статусын жаңарту» сценарийін көрсетеді.

**Проблема:** сұрыптау немесе тасымалдау кезінде жаңа ақпарат уақытында енгізілмесе, пайдаланушы жүйеде соңғы сақталған ескі статусты көреді. Бұл жүйе нақты уақытта GPS арқылы қозғалысты анықтамайды.

**Кодтағы шешім:** қызметкер жаңа расталған статус пен түсініктемені енгізеді. `Parcel.updateStatus()` ауысудың рұқсат етілгенін тексеріп, ағымдағы статусты өзгертеді және уақыт белгісімен `TrackingEvent` қосады. `ParcelDao.updateStatus()` ағымдағы статус пен тарих оқиғасын SQLite-ке бір транзакциямен сақтайды. Кейін трек-нөмір арқылы іздегенде соңғы сақталған статус және тарих көрсетіледі.

## 5. Activity диаграммасы

**Файлдар:** `activity-diagram.puml`, `activity-diagram.png`

Activity диаграммасы консоль мәзірінен сәлемдемені тіркеуді, міндетті деректер мен салмақты тексеруді, бірегей трек-нөмір генерациясын, ParcelFactory арқылы объект жасауды және SQLite транзакциясымен сақтауды көрсетеді. Қате болғанда транзакция rollback орындалады.

## 6. State диаграммасы

**Файлдар:** `state-diagram.puml`, `state-diagram.png`

State диаграммасы `DeliveryStatus` enum тізіміне және `canTransitionTo()` әдісіндегі нақты рұқсат етілген ауысуларға сәйкес келеді:
- REGISTERED → ACCEPTED;
- ACCEPTED → IN_TRANSIT;
- IN_TRANSIT → ARRIVED_AT_OFFICE немесе LOST;
- ARRIVED_AT_OFFICE → IN_TRANSIT, DELIVERED немесе LOST;
- DELIVERED және LOST — соңғы күйлер.

## 7. ER диаграммасы және деректер қоры схемасы

**Файлдар:** `er-diagram.puml`, `er-diagram.png`

SQLite деректер қорында бес кесте бар:
1. `senders` — жіберушілер;
2. `recipients` — алушылар;
3. `post_offices` — пошта бөлімшелері;
4. `parcels` — сәлемдемелер;
5. `tracking_events` — статус тарихы.

Кестелерде Primary Key (PK), Foreign Key (FK), міндетті өрістер және бірегей трек-нөмір шектеуі қолданылады. Бір сәлемдемеге бірнеше статус оқиғасы тіркеле алады.

## 8. Қорытынды

UML құжаттамасы нақты Java 17 консольдік қосымшасының моделін сипаттайды. Негізгі сценарийлер, OOP құрылымдары және SQLite кестелері кодтағы атаулар мен іске асырылған операцияларға сәйкестендірілген.
